# AI 행동·신뢰 규칙

OpenAI **두 역할** (한 API 키, 두 모델): [ADR-0002](../adr/0002-openai-two-model-stack.md)

| 역할 | 모델 (MVP) | 입력 |
| --- | --- | --- |
| 받아쓰기 | gpt-transcribe | 오디오 조각 |
| 제목·요약·할 일·챗 | gpt-5.6-luna | 받아쓰기 텍스트 + (필요 시) 내 메모 |

ChatGPT 웹앱 구독으로는 이 파이프라인을 **자동화할 수 없다**. 서비스는 **OpenAI API**를 사용한다.

---

## 내 메모 vs AI (신뢰)

| 규칙 | |
| --- | --- |
| 충돌 | **둘 다 표시**, 자동 병합 없음 |
| 최종 권위 | **사용자 편집** |
| 재생성 | **AI 영역만**; 내 메모 불변 |
| 표현만 다름 | 토스트 경고 없음 (handoff) |

요약·할 일 재생성 시 **이미 완료한 할 일·사용자가 수정한 할 일 문구**를 지우지 않는다. AI가 새 항목을 제안하면 **추가 또는 사용자가 정리**하는 쪽을 기본으로 한다 (자동 삭제 금지).

---

## 요약 형식 (제품)

- 안건별, 등장 순.
- bullets + 선택적 `결정:`.
- 할 일은 별 목록; 요약 불릿에만 숨기지 않음.
- Copy에 **「30초」 약속 금지**.

UX 상세: [ui-ux/handoff/05-product-policies.md](../ui-ux/handoff/05-product-policies.md)

---

## 제목

- AI는 **주제(topic)** 만 제안.
- 앱이 **날짜 접두** 부여.
- ④에서 사용자 확인 후 저장; empty → `{date} ({요일}) · 회의`.

---

## 받아쓰기·재생

- OpenAI `gpt-transcribe`는 공식 **단어/구간 타임스탬프를 주지 않음**.
- MVP: **30~60초 조각** 단위로 받아쓰기하고, 조각 시작 시각을 재생 좌표로 쓴다.
- **초 단위 정확도는 약속하지 않음** — handoff와 동일.
- 재생 정확도가 제품을 깨면 받아쓰기만 `whisper-1`로 교체 검토 (ADR-0002 보조).

---

## 챗봇

- 근거: 해당 회의의 받아쓰기·요약·할 일·메모·메타.
- 기록에 없으면 추측하지 않고 범위 밖 메시지.
- 다른 회의 내용을 섞지 않음.

---

## 실패

| 상황 | 행동 |
| --- | --- |
| STT 실패 | memo + audio 유지, `ai_failed`, 요약 재시도 |
| LLM 실패 | 동일 |
| 5분+ 지연 | ④에서 memo + audio OK, AI 영역 「다시 시도」 (handoff) |

사용자에게 **API 오류 코드·모델명** 노출하지 않음.

---

## 품질 검증 (운영)

- 첫 **실제 수요일 회의 1건**으로 한국어 받아쓰기·할 일 추출을 검수한다.
- 기준 미달 시: 프롬프트 조정 → 모델 tier 상향(Terra) → STT를 whisper-1 순으로 대응.

---

## 데이터 처리 위치

회의 음성·받아쓰기·요약·챗은 **OpenAI API**로 처리한다 (ADR-0002). MVP에서 로컬 STT·다른 AI 공급자는 두지 않는다.
