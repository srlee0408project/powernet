# 데이터 의미 (Data Semantics)

테이블·컬럼 DDL이 아니라, **각 덩어리가 제품에서 무엇을 뜻하는지**와 **무엇이 덮어씌워지면 안 되는지**를 정의합니다.

---

## Meeting (회의)

**의미:** 수요일(또는 사용자가 녹음한) 한 번의 회의 세션 하나.

| 개념 | 설명 |
| --- | --- |
| 제목 | `{날짜} ({요일}) · {주제}` — 날짜 접두는 앱, 주제는 AI, ④에서 사용자 최종 확정 |
| 처리 상태 | [plan.md](../plans/mvp-engineering/plan.md) §5 ①축과 동일 문자열 |
| 오디오 보유 | `available` / `expired`(90일 정리) / `none`(처음부터 없음) — §5 ②축 |
| 종료 시각 | 90일 만료 계산의 **유일한 기준** |
| 내 메모 | 사용자가 ②④에서 쓴 텍스트. **AI·재생성이 절대 덮지 않음** |

---

## Transcript (받아쓰기)

**의미:** 회의 음성을 글자로 바꾼 결과. **화면에 전문을 펼치지 않는다** (handoff non-goal).

| 개념 | 설명 |
| --- | --- |
| 구간 | 시작·끝 시각(ms) + 텍스트. 재생 seek·챗봇 근거 |
| 보존 | AI 요약이 틀려도 원문 텍스트는 남아 재생성·챗봇에 사용 |
| 오디오 만료 후 | 텍스트는 **그대로 유지** — 챗봇·요약 재생성은 계속 가능, 재생만 불가 |
| 발언자 | 저장하지 않음 (도메인 결정) |

받아쓰기 재실행은 **비용·시간**이 크므로, MVP 기본은 **요약만 재생성**하고 받아쓰기는 고정. 정책 변경 시 ADR 추가.

---

## Summary (요약)

**의미:** 안건(주제)별로 등장 순 정렬된 AI 요약.

| 개념 | 설명 |
| --- | --- |
| Section | 제목, bullets, 선택적 「결정:」 한 줄 |
| 할 일과 분리 | 할 일은 별 엔티티; 요약 불릿에만 섞지 않음 |
| 재생성 | AI 요약 블록만 교체. 내 메모·할 일 사용자 수정분 유지 |

---

## Todo (할 일)

**의미:** 사용자가 ④에서 **가장 먼저 확인**하는 실행 항목.

| 필드 의미 | 규칙 |
| --- | --- |
| 내용 | AI 초안, 사용자 수정 가능 |
| 마감 | **텍스트** (캘린더·알림 없음) |
| 요청자 | 맥락 추정 → UI 「요청 추정」, 틀리면 수동 |
| 안건 | 어떤 주제에서 나왔는지 |
| 재생 시각 | 선택. `play_clip`용 ms, 근사치 허용 |
| 완료 | 사용자 체크. ⑤ 필터 `open_todo_count`에 반영 |

재생성 시: **완료된 할 일·사용자가 고친 텍스트는 삭제하지 않는다** (병합 정책은 convention).

---

## Job (처리 작업)

**의미:** ③에 대응하는 백그라운드 파이프라인 실행.

- 단계(업로드 확인 → 받아쓰기 → 요약 등)는 UX steps와 **같은 순서**로 이해할 것.
- 실패 시 사용자에게 기술 상세 노출 금지; `ai_failed` + soft copy.

---

## Chat (챗봇)

**의미:** **해당 meeting_id 한 건**의 받아쓰기·요약·할 일·메타만 근거로 답함.

| 규칙 | |
| --- | --- |
| 범위 밖 질문 | 「이 회의 기록에 없어요」+ 할 일 링크 (handoff) |
| 회의 전환 | 위젯 닫기, in-memory 스레드 초기화 |
| MVP | 대화 로그 DB 영구 저장 **하지 않음** (비용·개인정보 최소) |

---

## 삭제·보존

| 트리거 | 오디오 | 회의·할 일·요약·메모·받아쓰기 |
| --- | --- | --- |
| **90일 자동** (확정) | Storage에서 **삭제** | **유지** — 목록·챗봇·할 일 계속 |
| **사용자 「회의 삭제」** | 삭제 | **전부** hard delete |

**오디오만 없어진 회의**

- `Meeting`은 목록에 남는다. 재생·오디오 탭은 불가; 챗봇·요약·할 일은 텍스트 근거로 동작.
- `play_clip` / seek: 오디오 없으면 재생 UI 비활성 또는 안내 (초 단위 seek 불필요).
