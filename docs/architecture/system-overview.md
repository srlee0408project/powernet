# 시스템 개요

## 한 장 그림 (논리)

```
[사용자 · Chrome · 노트북]
        │
        ├─ 회의 중: 마이크 → 브라우저 녹음 조각 → 로컬 임시 저장(IndexedDB)
        │            └─ 동시에 「내 메모」 편집
        │
        ├─ 종료: 조각 합치기 → 클라우드 파일 저장(직접 업로드)
        │         └─ 회의 메타·메모 → DB
        │
        └─ 처리(백그라운드): 받아쓰기(OpenAI) → 텍스트 저장
                              → 요약·할 일·제목(OpenAI) → DB
                              → 상태 ready / ai_failed

[다른 날] 목록·상세·재생·챗봇 ← DB + 파일 URL (회의 1건 컨텍스트)
```

**원칙:** 회의 중에는 서버가 거의 필요 없다. 무거운 일은 **종료 후**이며, 사용자는 ③에서 기다리거나 목록으로 빠져 나갈 수 있다(handoff).

---

## 구성요소 역할

| 구성요소 | 역할 | MVP에서 왜 |
| --- | --- | --- |
| 브라우저 화면 | 녹음, 로컬 버퍼, 업로드 시작, 화면 조작 | 노트북 하나로 끝나는 TO-BE |
| Next.js 서버 | 세션 확인, DB 조회·수정, signed URL 발급, job 요청 | 브라우저가 DB·키에 직접 닿지 않게 |
| Postgres | 회의·할 일·요약·받아쓰기 텍스트·작업 상태 | 구조화된 조회·필터 |
| Object Storage | 오디오 파일 | 1~2시간 바이너리는 DB에 넣지 않음 |
| 백그라운드 워커 | 받아쓰기·LLM 호출 체인 | HTTP 요청 시간 제한 회피 |
| OpenAI API | STT + 요약/챗 | 단일 AI 공급자 |
| 앱 세션(비밀번호) | API 게이트 — 본인만 데이터 접근 | Supabase Auth·RLS 미사용 |

## 회의 1건 생애

1. **시작** — 사용자가 녹음 시작. 사전 설정·참석자 등록 없음.
2. **진행** — 음성은 주기적으로 로컬에 flush. 메모는 사용자 입력 그대로.
3. **종료** — 업로드 + DB에 `recording` 종료 시각. 실패 시 로컬에 원본 유지.
4. **처리** — `processing`. 받아쓰기 조각 병렬/순차 후 텍스트 병합.
5. **준비** — 제목·요약·할 일이 **~2분** 목표로 ④에 노출 가능. 지연 시 handoff 로딩 정책.
6. **저장** — 사용자가 ④에서 제목·할 일 확인 후 저장. 이후 ⑤⑥⑦.
7. **소비** — 목록에서 제목으로 찾기, 할 일 완료, 챗봇 또는 구간 재생.

8. **정리** — 회의 종료 후 **90일**이 지나면 정리 job이 오디오만 삭제하고 오디오 보유를 `expired`로 바꾼다. 목록·할 일·요약·챗봇은 그대로다.

memo-only 경로: 오디오 없이 메모만 저장(녹음 누락·실패). 받아쓸 음성이 없으므로 AI는 돌리지 않는다.

## 경계: 무엇이 어디에 있나

| 데이터 | 회의 중 | 업로드 후 | 90일 후 |
| --- | --- | --- | --- |
| 음성 | IndexedDB | Storage | **삭제** |
| 내 메모 | IndexedDB(선택 동기) + DB | DB | DB |
| 받아쓰기 텍스트 | 없음 | DB (UI 미노출) | DB |
| 요약·할 일 | 없음 | DB | DB |

다른 PC에는 IndexedDB가 없다. 클라우드에 올라간 것만 어디서든 열린다.

---

## 실패·복구 (아키텍처 관점)

| 실패 | 설계 대응 |
| --- | --- |
| 로컬 버퍼 없이 메모리만 사용 | 1~2시간 손실 → IndexedDB 필수 |
| 앱 서버 경유 대용량 업로드 | 타임아웃·비용 → Storage 직접 업로드 |
| 동기 HTTP로 STT 90분 | 불가 → 워커 + 상태 머신 |
| STT API 25MB/파일 제한 | 서버/워커에서 분할·병합 (정책은 convention) |

세부 UX 문구·버튼은 handoff 06.

---

## 의도적으로 두지 않는 것

- 벡터 DB / 회의 간 semantic search (챗봇은 1건 full context)
- 실시간 STT UI (종료 후 처리)
- 멀티 테넌트·팀 ACL
